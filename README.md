# SportMarket — MVP

Маркетплейс спортивной экипировки с верификацией продавцов (по ПР-02 и ПР-03).

## Запуск

```powershell
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

Откройте http://127.0.0.1:8000. Документация API: http://127.0.0.1:8000/docs.

При первом запуске создаются администратор и демо-данные:

Тесты: `pytest`.

## Что входит в MVP (User Story Map, ПР-02 задание 3)

| Экран | Что работает |
|---|---|
| P1 Вход / регистрация | email + пароль, выбор роли «покупатель / продавец», JWT |
| P2 Личный кабинет | профиль; у продавца — магазин, загрузка ИНН/ОГРН/паспорта, статус верификации, товары, заказы |
| P3 Товар (продавец) | название, описание, цена, категория, состав, срок доставки, размерная таблица, блоки «Технологии» и «Уход», фото и видео |
| P4 Аналитика | выручка, продажи, товары с продажами, рейтинг по каждому товару |
| P5 Каталог | поиск по названию, категории; только товары верифицированных продавцов |
| P6 Карточка товара | галерея, выбор размера, вкладки «Размерная таблица / Технологии / Уход / Состав», оценки |
| P7 Оформление заказа | корзина, способ доставки, адрес, способ оплаты, оплата, трек-номер |
| Оценка | после получения заказа — модальное окно со звёздами |
| Админ | проверка документов продавцов, одобрение / отказ с причиной |

Права доступа соответствуют матрице из ПР-03 (задание 2): покупатель не управляет товарами,
продавец не пользуется корзиной, чужие документы видит только администратор.

## Отличия от архитектуры ПР-03 (упрощения MVP)

| В архитектуре | В MVP | Как перейти |
|---|---|---|
| PostgreSQL | SQLite | `pip install "psycopg[binary]"`, `DATABASE_URL=postgresql+psycopg://...` |
| MinIO | папка `storage/` (`services.FileStorage`) | заменить `FileStorage` клиентом MinIO с тем же интерфейсом |
| ЮKassa | тестовая страница оплаты + webhook с HMAC-подписью | реализовать `create_payment` через SDK ЮKassa |
| Resend | письма пишутся в лог | задать `RESEND_API_KEY` |
| Celery + Redis | `BackgroundTasks` FastAPI | вынести `_order_confirmation_email` в задачу Celery |
| FastAPI Users | собственный JWT (`security.py`) | — |
| React + сборка | React через CDN, без Node.js | перенести `frontend/app.js` в Vite-проект |

Изменения модели данных относительно ER-диаграммы: у заказа есть позиции `OrderItem` и ссылка на
пользователя (у пользователя одна корзина, но много заказов); у отзыва есть `product_id`; у товара
есть состав, размерная таблица и срок доставки; у инструкции есть вид (`technology` / `care`).

Настройки задаются через переменные окружения или файл `.env` (см. `config.py`).

## Подготовка к интеграции с CRM Битрикс24 (ПР-05)

ПР-05 выполнена по быстрому пути, вариант A: CRM Битрикс24 на бесплатном тарифе настроена и готова к интеграции,
передача данных через REST API будет в ПР-08. Схема интеграции и таблица маппинга полей приведены в отчёте ПР-05.

Тестовые данные из `sportmarket.db` выгружаются в CSV для импорта в Битрикс24:

```powershell
python crm_export.py   # → crm/contacts.csv (5 контактов), crm/deals.csv (5 сделок)
```

| Файл | Что внутри | Куда импортировать |
|---|---|---|
| `crm/contacts.csv` | покупатели и продавцы: имя, e-mail, роль, магазин | «CRM → Контакты → ⚙ → Импорт контактов» |
| `crm/deals.csv` | заказы: сумма, стадия, контакт, доставка, оплата, трек-номер, состав, оценка | «CRM → Сделки → ⚙ → Импорт сделок» |

Перед импортом в Битрикс24:

1. Переименуйте стадии сделок: «Новая» → «Новый заказ», «Подготовка документов» → «Оплачен», «В работе» → «Отправлен».
2. Создайте пользовательские поля сделки: «Способ доставки» и «Способ оплаты» (список), «Адрес доставки», «Трек-номер»,
   «Состав заказа» (строка), «Дата оплаты» (дата/время), «Оценка покупателя» (число);
   поля контакта: «Роль в SportMarket» (список), «Магазин» (строка).
3. В мастере импорта выберите кодировку UTF-8, разделитель «;» и сопоставьте столбцы с одноимёнными полями.
   Сначала импортируйте контакты, затем сделки; в импорте сделок сопоставьте «Контакт» и «Рабочий e-mail»
   с полями контакта и включите контроль дубликатов по e-mail, чтобы сделка привязалась к уже загруженному контакту.
